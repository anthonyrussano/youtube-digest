## 02 Duolingo's test robots
Narration: Duolingo's iOS app is ten years old. Old code, few tests. So staff engineer Kush Agrawal let agents write the tests. Here's the loop. Temporal picks a file. Claude Code writes the tests. Then a little state machine pokes each open pull request, one action, every few hours. Who reviews it? Whoever git blame says touched that code last. Congratulations, you're the reviewer. Eight months later, coverage on the newer code went from nine percent to fifty-nine. About seven hundred pull requests. A human approved every one. And a judge model threw out seventy-three of them for sneaking edits into real code, or quietly muting tests. Nice try, robot.

## 03 What does the model already know?
Narration: Next. Intel's Nikolay Petrov asked a sneaky question. When you hand a model a skill file, how much of it did the model already know? His team chops each skill into twenty-five to thirty facts, and quizzes the model with the file and without it. Opus nailed seventy percent of the big ideas. But the exact details? Twenty-two percent. The whole test cost fourteen dollars for twenty-nine skills. So, cut what it knows. Keep the exact numbers. Save tokens.

## 05 The agent that tunes itself
Narration: DigitalOcean's Rohan Pandey built an agent that tunes vLLM, all by itself. It tries one setting per round and measures real speed. On GPT-OSS 120B, fifty rounds bought seventeen and a half percent more tokens. On a DeepSeek R1 distill, just nine rounds doubled the speed and nearly halved the wait between tokens. It takes a few hours. Let it run while you sleep.

## 08 The GPU that lies
Narration: Here's a scary one. Silent data corruption. A GPU hands back a wrong number that looks totally fine, and raises no error at all. In fifty-four days of training Llama 3, Meta traced six interruptions to exactly this. AWS's fix? Make the GPUs check each other's homework. One GPU redoes another node's batch, and the answers must match, bit for bit.
