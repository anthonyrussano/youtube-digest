## 02 A CI stealer hits 61,764 repos
Narration: Aikido's Oliver Smith traced a campaign that started November tenth. Stolen GitHub credentials planted a workflow that dumps Actions secrets, runner memory, and AWS, GCP, and Azure tokens, then deletes the run logs. Aikido confirmed the payload ran in at least one thousand eight hundred and six repositories, and it already poisoned at least one open-source package. Hunt for a pull request titled "docs: dependency audit notes," often from a wfx-docs branch. Also look for commits named "ci: refresh build cache" or "chore: add ci helper." Ten thousand of those pull requests landed in repositories the account does not own, and ninety-two percent are still open. If the payload ran, assume total compromise. Rotate every repository secret, every AI provider key, and every cloud role.

## 03 What the model already knows

## 04 A cloud, on a laptop
Narration: AWS shipped AWS Emulator, a local program that serves AWS APIs on your machine. It listens on one two seven, zero, zero, one, port ninety-two ninety-seven, writes its own keys, and has no extra service fee. The access key IDs start with EMULATOR, so they are hard to mistake for real ones. Daniel Abib says it is written in Rust, so it stays light on a laptop. It is built from the same public API models the official SDKs use, and agents at AWS even maintain it as those models change. It does not evaluate IAM policies the way AWS does, and each copy is a single account. Operations it has not implemented yet return HTTP 501, so a test fails right away, instead of silently lying.

## 05 Getting out of the loop
Narration: Getting out of the loop is the easy part. Keeping it safe is harder. In that August study, auto mode blocked eighty-nine percent of clearly dangerous commands, and people caught only fourteen percent. About one in ten still got through. Deny rules still win, because Claude Code checks them before the auto mode classifier even looks. A sandbox can limit which files, folders, and hosts a command and its child processes can touch. That matters when npm test runs code you did not write. Even then, MCP servers and hooks run outside the sandbox. A cloud session gets its own machine and a fresh copy of the repo. Your .env file and SSH keys are not there, and the job can keep running with your laptop closed. For checks that must run, Hallie says use hooks, and make a failing test exit with code 2, not 1. Exit code 1 marks the task done anyway.
