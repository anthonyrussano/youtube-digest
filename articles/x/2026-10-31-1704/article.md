Coding agents now write a pull request in minutes, and then the pull request sits there. Vox found each one waiting [up to 40 minutes for CI, and nine fixes brought that down to 2](https://x.com/Voxyz_ai/status/2116636332344889391). Meanwhile, Snorkel AI was spending about 20 minutes restoring a database for every test environment, until [copy-on-write branches made a fresh copy of production ready in under a minute](https://www.databricks.com/blog/lakebase-branching-cicd-lessons-100-pr-databases).

Here is what happened in AI and DevOps this cycle.

Vox's team pushes dozens of pull requests a day with Claude Code and Codex, so the slow part of shipping stopped being the code and became the wait. The first move wasn't tuning anything. It was measuring: an agent pulled [the last 150 CI runs with the GitHub CLI and split every job into three buckets](https://x.com/Voxyz_ai/status/2116636332344889391), time spent queued for a machine, time spent on setup like checkout and dependency installs, and time actually running tests. That one table showed half the test jobs had been ignoring the dependency cache for about a year. Nobody had noticed, because nobody had ever broken the number apart.

The nine checks that followed are boring in the best way. Are jobs queueing on the default runners? Are lint and typecheck slower than they should be? Are tests unsharded, or running on machines that are too small? Is every test file booting the whole app from scratch? Is setup missing the cache, cloning full history, or launching more parallel work than the machine has cores? Do jobs that could run side by side run one after another? Does every pull request run the full suite, even for a one-line change? Is anything checked locally before the push? The prompt asks the agent for the seconds lost on each, the file and line to change, and the estimated savings, with a separate list for anything that costs money or runs fewer tests. Its best line is the last one: "Give me the report first. Don't change anything."

Snorkel AI hit the same wall from the data side. Every pull request gets its own short-lived Kubernetes environment, and each one needed a realistic copy of a production Postgres database. Restoring that copy took about 20 minutes per environment. Now a replication service keeps a main copy within about two minutes of production, and CI asks Databricks Lakebase for a [copy-on-write branch of it for each pull request](https://www.databricks.com/blog/lakebase-branching-cicd-lessons-100-pr-databases), which means the branch shares the original's data and only stores what the tests change. Each branch is ready in under a minute and carries an expiry time so it deletes itself. Branching roughly a terabyte takes about as long as branching a gigabyte, a few seconds. The same post suggests giving each AI agent task its own branch, so you review what the agent did to the data, or throw the branch away.

Put those two stories together and you get the real lesson of this cycle. Agents made writing code nearly free, so every minute of waiting around the code is now the expensive part. Measure where the wait goes before you buy bigger machines.

Prasenjit Sarkar wrote up Google's Elephant-Goldfish Model, a planning setup he says Google has open-sourced. An Elephant agent stays with you for the whole feature and never writes code; [its job is to argue with you about the plan](https://x.com/stretchcloud/status/2116625003277881615). The plan moves from brainstorm to a written design that names files and function signatures, then to review by Goldfish agents that start with no memory at all. One Goldfish has to explain the plan back before it is allowed to critique it, others hunt for edge cases, and a last one makes the go or no-go call. Sarkar says thousands of Google engineers use it daily inside Antigravity. The trick is easy to steal: if a reviewer with zero context can't explain your plan, the plan isn't done.

Apek released AnyScene, which takes [one or more reference images plus optional text and has an agent build the whole set in Blender](https://x.com/apekshik/status/2116638903923073290): objects placed, lit, and color-graded, with every asset saved as its own file. The point is the last part. You don't get a flat picture back, you get a scene you can open and edit piece by piece.

A paper accepted at ICML 2026 introduces SDPO, short for self-distillation policy optimization. When a model fails, it looks at its own failed attempt alongside the environment's feedback, works out what it should have said, and [trains itself toward that corrected answer, with no outside teacher model](https://x.com/Pyuyi2333/status/2116622177805980065). On chemistry problems with Olmo3-7B, it reached the accuracy of GRPO, the standard reinforcement method, [about six times faster in wall-clock time](https://arxiv.org/abs/2601.20802). On hard coding problems it found solutions with up to three times fewer attempts. The authors flag the limits: it needs reliable feedback, a model capable enough to teach itself, and extra compute, and whether it generalizes beyond those tasks is still open.

Quinten Farmer ran the numbers on what it costs to serve open models. Using B200 spot pricing of about 5.70 dollars an hour and GLM-5's throughput at 80 percent utilization, he estimates [US providers serve open models at roughly 45 to 60 percent gross margin](https://x.com/quintendf/status/2116626710007566673). Zhipu, the lab behind GLM, reported 24.6 percent on its API business for the first half of 2026, up from slightly below zero. His read is that Chinese margins are thinner because of worse hardware and a smaller buildout, not a deliberate price war. It's a back-of-the-envelope estimate, and he notes the current GLM-5.3 prices came after the period Zhipu reported, but it pushes back on the idea that cheap open-model APIs must be losing money.

So which one are you trying first: the CI audit, a database branch for every pull request, or a memory-free reviewer for your plans?

That's the cycle. Split your CI time into three buckets, branch a database instead of restoring one, and let a goldfish read your plan.
