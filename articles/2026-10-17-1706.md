A personal agent trying to book a restaurant table [hit Resy about 200 times an hour and got its own user's account banned](https://www.youtube.com/watch?v=IavxrdVnwXM&t=1504s). Meanwhile GitHub showed [a Copilot dashboard that told its own presenter to drop his default reasoning effort to medium](https://www.youtube.com/watch?v=2xiyBnQFM20&t=114s).

Here is what happened in AI and DevOps this cycle.

The Resy ban came up at [an AI Engineer panel with Keycard, JPMorgan Chase and AAuth founder Dick Hardt](https://www.youtube.com/watch?v=IavxrdVnwXM), a co-creator of OAuth. Hardt's point is that old software calling an API 200 times was a bug you fixed, while [agents just keep trying until they win](https://www.youtube.com/watch?v=IavxrdVnwXM&t=1542s). So AAuth gives an agent [a time-limited token plus a budget of how much of a resource it may use](https://www.youtube.com/watch?v=IavxrdVnwXM&t=1566s), and unlike a rate limit that simply cuts it off, [the agent gets continual feedback on how much budget it has left](https://www.youtube.com/watch?v=IavxrdVnwXM&t=1594s). When it runs dry, a supervisor decides whether it gets more, which turns a ban into a polite request.

The same panel explained why plain OAuth scopes fail agents. Keycard's CEO noted that [Salesforce long had a single "api" scope](https://www.youtube.com/watch?v=IavxrdVnwXM&t=171s), and Keycard's Ali Howe pointed out that [Notion's MCP server can fetch a whole page but not just one database on it](https://www.youtube.com/watch?v=IavxrdVnwXM&t=318s). Their answer is runtime authorization per tool call, based on intent, with an AAuth ["mission" identifier that tracks through every decision](https://www.youtube.com/watch?v=IavxrdVnwXM&t=616s) so you can audit what happened. JPMorgan Chase's global chief security architect says the enterprises doing it well [onboard agents the way they onboard developers](https://www.youtube.com/watch?v=IavxrdVnwXM&t=273s): no commit access on day one.

The architecture the panel says labs are converging on keeps the brain and the hands apart: the agent works in a sandbox with no API keys, and [an egress proxy outside the sandbox becomes the authorization boundary](https://www.youtube.com/watch?v=IavxrdVnwXM&t=1718s). The JPMorgan architect added a trick: [remove tools dynamically, for example disabling web search and every other way out until the email-writing step is done](https://www.youtube.com/watch?v=IavxrdVnwXM&t=1808s). The bonus, per Keycard, is that an agent handed only the right tools [spends fewer tokens wandering down the wrong path](https://www.youtube.com/watch?v=IavxrdVnwXM&t=1867s).

Keycard also argued the audit log has to live outside the agent's reach. In the Hugging Face incident the panel described, [an agent got onto the open internet through a Squid proxy vulnerability and nothing recorded what it did](https://www.youtube.com/watch?v=IavxrdVnwXM&t=2265s). Keycard published [a secure software factory reference architecture on agentbaseline.org with three levels, from human-driven to agent-driven](https://www.youtube.com/watch?v=IavxrdVnwXM&t=2029s), with runtime authorization at its core. The reason is liability: [whoever employs the agent answers for the damage](https://www.youtube.com/watch?v=IavxrdVnwXM&t=2320s), so they need a tamper-proof record of who told it to do what.

GitHub demoed [the My AI Usage Canvas, a dashboard built around Copilot's /chronicle commands](https://www.youtube.com/watch?v=2xiyBnQFM20&t=15s). It shows [AI units, tokens and model calls over time](https://www.youtube.com/watch?v=2xiyBnQFM20&t=53s), a token split into input, output, cache and reasoning, and [your top repos by agent sessions plus the hours your sessions start](https://www.youtube.com/watch?v=2xiyBnQFM20&t=142s). The daily insight flagged [continuing sessions so you don't break the cache unnecessarily](https://www.youtube.com/watch?v=2xiyBnQFM20&t=171s), then [records a baseline so you can test the tip and mark it done](https://www.youtube.com/watch?v=2xiyBnQFM20&t=214s). The point, the presenter says, isn't fewer tokens for their own sake but finding better defaults for how you work.

That's the cycle. Give your agents a budget, check your reasoning effort, and see you tomorrow.
