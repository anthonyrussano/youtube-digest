Aikido found [4,837 compromised GitHub accounts trying to push a secret-stealing workflow into 61,764 repositories](https://www.aikido.dev/blog/compromised-github-accounts-push-ci-secret-stealer-to-tens-of-thousands-of-repositories). Meanwhile [only 14% of people in an Anthropic study caught a clearly dangerous command](https://www.youtube.com/watch?v=vlfCjWuv4es&t=349s). Auto mode blocked 89% of them.

Here is what happened in AI and DevOps this cycle.

Aikido's Oliver Smith [traced a new campaign that started on November 10](https://www.aikido.dev/blog/compromised-github-accounts-push-ci-secret-stealer-to-tens-of-thousands-of-repositories). Stolen GitHub credentials planted a workflow that [dumps Actions secrets, runner memory, and AWS, GCP and Azure OIDC tokens](https://x.com/AikidoSecurity/status/2120720220629180540), then [deletes the run logs](https://x.com/AikidoSecurity/status/2120720228283760754). Aikido confirmed the payload ran in [at least 1,806 repositories](https://www.aikido.dev/blog/compromised-github-accounts-push-ci-secret-stealer-to-tens-of-thousands-of-repositories), and it already [poisoned at least one open-source package](https://x.com/AikidoSecurity/status/2120720228283760754) through automated publishing. Hunt for a pull request titled ["docs: dependency audit notes"](https://x.com/AikidoSecurity/status/2120720230708044169), often from a `wfx-docs` branch. Also look for commits named "ci: refresh build cache" or "chore: add ci helper". [10,431 of those pull requests landed in repositories the account does not own](https://www.aikido.dev/blog/compromised-github-accounts-push-ci-secret-stealer-to-tens-of-thousands-of-repositories), and [92% are still open](https://www.aikido.dev/blog/compromised-github-accounts-push-ci-secret-stealer-to-tens-of-thousands-of-repositories). If the payload ran, Aikido says to [assume total compromise and rotate every repository secret, AI provider key, and cloud role](https://x.com/AikidoSecurity/status/2120720230708044169). The firm notes overlap with the October GhostAction accounts, but it does not pin this wave on the same actor.

Lydia Hallie of Anthropic's [Claude Code team says the old steering tricks now get in the way](https://www.youtube.com/watch?v=vlfCjWuv4es). Anthropic went from [about 2,500 changes a day in May to more than 30,000 a day in September](https://www.youtube.com/watch?v=vlfCjWuv4es&t=105s). Teams there now [run dozens of sessions at once, for hours](https://www.youtube.com/watch?v=vlfCjWuv4es&t=83s), and some sessions start others. She says shouting "important" in a CLAUDE.md file [can send today's models off track and produce more tool calls](https://www.youtube.com/watch?v=vlfCjWuv4es&t=199s). Keep only what the model cannot see in the code, and run [doctor prompt audit](https://www.youtube.com/watch?v=vlfCjWuv4es&t=235s) to drop the rest. Auto mode became the [default permission mode in August](https://www.youtube.com/watch?v=vlfCjWuv4es&t=186s).

AWS shipped [AWS Emulator, a local program that serves AWS APIs on your machine](https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/). It listens on 127.0.0.1 port 9297, writes its own keys, and has no extra service fee. The access key IDs start with EMULATOR, so they are hard to mistake for real ones. Daniel Abib says it is [written in Rust so it stays light on a laptop](https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/). It is [built from the same public API models the official SDKs use](https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/). Agents at AWS even [maintain it as those models change](https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/). It does not [evaluate IAM policies the way AWS does](https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/), and each copy is a single account with no cross-account or cross-region behavior. Operations it has not implemented yet [return HTTP 501](https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/), so a test fails right away instead of silently lying.

Getting out of the loop is the easy part. Keeping it safe is harder. In that [August study, auto mode blocked 89% of clearly dangerous commands, and people caught only 14%](https://www.youtube.com/watch?v=vlfCjWuv4es&t=349s). About 1 in 10 still got through. [Deny rules still win](https://www.youtube.com/watch?v=vlfCjWuv4es&t=372s), because Claude Code checks them before the auto mode classifier even looks. A sandbox can [limit which files, folders, and hosts a command and its child processes can touch](https://www.youtube.com/watch?v=vlfCjWuv4es&t=497s). That matters when `npm test` runs code you did not write. Even then, MCP servers and hooks [run outside the sandbox](https://www.youtube.com/watch?v=vlfCjWuv4es&t=554s). A [cloud session gets its own machine and a fresh copy of the repo](https://www.youtube.com/watch?v=vlfCjWuv4es&t=569s). Your `.env` file and SSH keys are not there, and the job can [keep running with your laptop closed](https://www.youtube.com/watch?v=vlfCjWuv4es&t=575s). For checks that must run, Hallie says use hooks, and make a failing test [exit with code 2, not 1](https://www.youtube.com/watch?v=vlfCjWuv4es&t=785s). Exit code 1 marks the task done anyway.

That's the cycle. Go search your repos for a "docs: dependency audit notes" pull request, make your hooks exit 2, and see you tomorrow.
