An airline crew scheduler used to get [15 minutes to recrew a broken flight by hand](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=25s), often settling for the one legal answer he could find. The engine Apollo built for that desk now [lists every option, ranked by cost, in under a minute](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=927s). Meanwhile Xiaomi shipped [a 0.8-billion-parameter model that turns photos of receipts and invoices into structured JSON](https://huggingface.co/xiaomi-research/Xiaomi-OCR-0).

Here is what happened in AI and DevOps this cycle.

Thetips4you walked through [running Claude Code against a model on your own GPU, with no API key and no token bill](https://www.youtube.com/watch?v=-Qvf9Y3RT_M). The trick is that [Ollama now speaks the same API format as Anthropic](https://www.youtube.com/watch?v=-Qvf9Y3RT_M&t=72s), so the agent thinks it is talking to the cloud while every request stays on localhost port 11434. Setup is three steps: install Ollama 0.15 or newer, pull a coding model, then run [`ollama launch claude`](https://www.youtube.com/watch?v=-Qvf9Y3RT_M&t=238s) and pick the model from a list. Ollama's own docs show the same command, plus a manual route with three environment variables that point Claude Code at localhost.

The catch is memory, and the video calls it the context trap. On GPUs with less than 24 GB, [Ollama's default context is only about 4,000 tokens](https://www.youtube.com/watch?v=-Qvf9Y3RT_M&t=289s), which an agent burns through after reading two files. Nothing errors. The model quietly forgets what it read, rereads the file, and edits the wrong thing, and people blame the model. The fix is [starting the server with `OLLAMA_CONTEXT_LENGTH=65536`](https://www.youtube.com/watch?v=-Qvf9Y3RT_M&t=319s), and Ollama's Claude Code page gives the same advice: 64K or more for real repositories.

Then check that it fits. Run [`ollama ps` while the agent works and look for 100% GPU](https://www.youtube.com/watch?v=-Qvf9Y3RT_M&t=366s) next to your new context size. Spill into system RAM and the CPU takes over, and speed collapses from [the 50 to 65 tokens per second a 35B model hits on an RTX 3090](https://www.youtube.com/watch?v=-Qvf9Y3RT_M&t=387s) down to single digits. The host's verdict is honest: local wins on cost, privacy and offline work, but [top cloud models still handle large refactors and long multi-step tasks much better](https://www.youtube.com/watch?v=-Qvf9Y3RT_M&t=532s). Use the local model for daily edits and private code, keep permission prompts on, and switch to the cloud for the hard problems.

Adam Nahari of Apollo opened his AI Engineer talk with an awkward gap. [55% of US adults have used generative AI, and almost 90% of businesses use it somewhere](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=82s), yet only 6% of companies attribute 5% or more of EBIT to it. He compares it to Robert Solow's 1987 line about seeing computers everywhere except the productivity statistics. His explanation is a ratio: [five units of change management for every one unit of engineering](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=171s), and the engineering share shrinks as models improve.

Nahari's crew-scheduling story shows what that looks like. Crew is an airline's [second-largest cost after fuel](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=67s), so Apollo picked that one problem instead of running 40 pilots. The 10% version would have given schedulers a faster tool. The 10x version was [an optimization engine that weighs rest rules, qualifications and pilot locations, then ranks every legal solution by cost](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=484s), plus a rebuilt workflow around it. Even so, he says [the engineering was the smaller job; getting people to use it was the bigger one](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=537s).

The rest of his playbook is blunt. [He won't fund an initiative until the CEO has publicly called it a priority](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=550s). Schedulers met the engineers every other day and designed the interface with them, so they adopted the tool because they built it. Every pilot gets kill metrics up front: [90 days per stage, A/B tests against an agreed baseline, and adoption above 50% of schedulers](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=784s), and the CFO checks that compute, tokens and staff at scale cost far less than the payoff. His most quotable detail: in one executive workshop on redesigning the business with AI, [three out of four people had never used an AI tool before that week](https://www.youtube.com/watch?v=vUJDyDnqT4c&t=719s).

Researchers at NVIDIA and MIT reportedly [pointed Karpathy's improvement loop at the agent harness instead of the model](https://x.com/Mr_Buzzoni/status/2117133855333200155) and cut the API bill by 50 to 54%. Same models, same benchmark; only the scaffolding around Claude Code and Codex changed, according to Mr_Buzzoni's summary of the work. The loop itself is plain: propose, implement, review, test, then keep or discard. If the result holds up, the cheapest upgrade available might be the wrapper you already run, not a bigger model.

Cloudflare's DNS team [stopped rebuilding whole zones every time a zone setting changes](https://blog.cloudflare.com/dns-targeted-zone-builds/). Its Zone Builder now takes about 700 record changes a second, nearly three times the 2022 rate, and some zones hold more than 20 million records. A new planner picks the smallest build it can prove is safe and a scheduler batches work for the same zone, which cut peak memory by 85% and halved the time from a DNS change to its data landing in Quicksilver, Cloudflare's distributed key-value store. Speed was never the hard part; proving a smaller build could not leave stale records at the edge was.

IBM Technology made the case that [a one-sentence prompt can't explain years of decisions in a codebase](https://www.youtube.com/watch?v=EkdIZXDnRK8&t=36s), so an agent asked for a login endpoint will guess at your auth library and folder layout. Its sneakiest point is dependencies: [the agent needs the exact version from your lock file](https://www.youtube.com/watch?v=EkdIZXDnRK8&t=145s), because many hallucinated functions are really version mismatches. The cheapest fix is to [open with "interview me and ask me questions until you understand what you need"](https://www.youtube.com/watch?v=EkdIZXDnRK8&t=242s), then have the agent save what it learned in an AGENTS.md. And don't dump in the whole repo, since [models pay the most attention to the start and end of a long input](https://www.youtube.com/watch?v=EkdIZXDnRK8&t=302s) and every irrelevant file competes with one that matters.

India's Ministry of Electronics and Information Technology wants AI models trained on local data without handing that data over. Its DEPA for AI Training plan works so that [the model travels to the data, rather than the data travelling to the model](https://www.theregister.com/public-sector/2026/11/02/india-floats-ai-plan-under-which-the-model-travels-to-the-data-rather-than-the-data-travelling-to-the-model/5306872). Hospitals, banks and agencies would share anonymized, encrypted data with exchange platforms that run hardware-based secure environments, where model builders train under the data owner's rules, with differential privacy applied and every action logged for audit. The ministry pitches it as a way to extend formal credit to 400 million underserved people and businesses. It is unclear how much work remains before it runs.

Xiaomi's research team built that receipt reader, [Xiaomi-OCR-0](https://huggingface.co/xiaomi-research/Xiaomi-OCR-0), on Qwen3.5-0.8B and trained it on about 170 million OCR samples. Hand it a document image and it returns Markdown with tables and LaTeX formulas in reading order. Hand it a JSON schema with fields like seller name and total tax, and it fills them in. FHILY's [rundown of the release](https://x.com/Oluwaphilemon1/status/2117068641082749040) stresses that it understands the document rather than only transcribing it. The model is Apache 2.0, small enough for a laptop, and its own technical report puts it at 59.09% on Xiaomi's in-house extraction benchmark, so check its fields before your accounting system trusts them.

Pieter Levels argued that [passkeys behave like passwords, not like a second factor](https://x.com/levelsio/status/2117203383853436969). They are supposed to need biometrics, but in practice they sit in a password manager, and opening that manager hands them over. Any security review that counts a passkey as 2FA is counting one factor twice.

Yonas Beshawred shared [a one-line prompt that has a coding agent check a repository against 80+ GitHub Actions optimizations](https://x.com/yonasbe/status/2117129569757245616). It tells the agent to install a "ci-speedup" skill with `npx` from [StarSling's skills repository](https://github.com/starslingdev/skills) and then follow whatever instructions it generates. Faster CI is a fine goal. Read the skill file before an agent runs it, for the same reason the Ollama video says to keep permission prompts on.

Docker laid out [three ways to hand a coding agent your code inside a Docker Sandbox](https://www.docker.com/blog/docker-sandbox-code-checkout-workflows/). Running `sbx run claude` from a project mounts it at the same path, so you watch edits live, but native packages like esbuild installed in the Linux sandbox can break on a macOS host. A mounted Git worktree can't reach its .git metadata, so commits happen on the host, while clone mode mounts your source read-only and gives the agent its own independent clone. Pick the layout by how much of the work you are handing over.

Joscha Bach spent [97 minutes with Machine Learning Street Talk on why Leibniz couldn't find the mind inside the mill](https://www.youtube.com/watch?v=yW_ngvMFlYs), and his boldest claim is that [consciousness might be a biological learning algorithm](https://www.youtube.com/watch?v=yW_ngvMFlYs&t=2006s), the simplest way to train a self-organizing brain. He points to infants: [if consciousness never ignites, the child forms no world model and never learns language](https://www.youtube.com/watch?v=yW_ngvMFlYs&t=1983s). His machine version follows: [restrict today's machines to self-organizing learning](https://www.youtube.com/watch?v=yW_ngvMFlYs&t=2084s), and one might [go through a phase transition that suddenly lets it learn](https://www.youtube.com/watch?v=yW_ngvMFlYs&t=2104s). That is a test no Turing test can run, because Turing only scores performance.

Daniel Lockyer has a tidy CI trick: [give your agent a GitHub Actions run link and ask it for a .pftrace file](https://x.com/DanielLockyer/status/2117224680943690023), then upload that file to Perfetto to see every job laid out on one timeline. One prompt turns a slow pipeline into a picture of which job blocks the rest.

FHILY also relayed a report that [one RTX 3090 is serving 64 concurrent Qwen3.8-27B sessions at more than 1,000 tokens per second of combined throughput](https://x.com/Oluwaphilemon1/status/2117064335893610500), on 24 GB of VRAM power-limited to 250 watts, with no second GPU. Treat it as a claim until someone publishes the setup. If it holds, a used gaming card starts to look like a small team's inference server.

Darryl Ruggles, an AWS Hero, makes the case that [a little time on your Dockerfile cuts build times and shrinks images](https://x.com/RDarrylR/status/2117127112637170119). Most images pull a base, install packages, and ship plenty that never runs in production. The usual fixes are ordering layers from least to most volatile, keeping the build context small with a `.dockerignore`, and multi-stage builds that leave compilers behind.

Addy Osmani says he [runs five to ten agents in parallel](https://www.oreilly.com/radar/practical-loop-engineering/), and his loop engineering guide maps the Claude Code team's ladder of loops. `/goal` keeps Claude iterating until a measurable finish line, such as getting a Lighthouse score to 90 or above with a 5-try limit, and an evaluator model checks the condition every time Claude tries to stop. `/loop 5m` reruns a prompt on a timer, and `/schedule` moves it to the cloud. His warning is the useful part: a loop left alone without a well-defined goal and constraints can leave an old codebase in a worse state.

Kushal Gangil published [a 15-visual guide to platform engineering for people already in cloud or DevOps](https://x.com/techyoutbe/status/2117156770057781529), covering Backstage, golden paths, Crossplane and GitOps. If Nahari is right that adoption is the hard part, a golden path is the same idea for internal tools: make the right way the easiest way.
