One team took each pull request's CI run [from up to 40 minutes down to 2 with nine changes](https://x.com/Voxyz_ai/status/2116636332344889391), and found a cache bug that had sat unnoticed for a year. Meanwhile Snorkel AI gives every open pull request [its own writable copy of a production Postgres database in under a minute](https://www.databricks.com/blog/lakebase-branching-cicd-lessons-100-pr-databases).

Here is what happened in AI and DevOps this cycle.

Vox argues that Claude Code and Codex now push dozens of PRs a day, so the bottleneck has moved from writing code to waiting on CI. The first of the nine fixes was diagnostic: an agent pulled [the last 150 CI runs and split every job into waiting for a machine, setup and actual running](https://x.com/Voxyz_ai/status/2116636332344889391). That split alone showed half the test jobs weren't using the dependency cache at all. The shared prompt asks the agent for a report first, with seconds lost per problem and the exact file line to change, and tells it not to touch anything yet.

Snorkel AI used to wait about [20 minutes to restore a database copy for each PR environment](https://www.databricks.com/blog/lakebase-branching-cicd-lessons-100-pr-databases), too slow for a merge queue that needs a fresh one every run. Now AWS DMS keeps a Lakebase main branch within about 2 minutes of production Aurora, and each PR gets a copy-on-write branch that shares storage with main and adds only about 5 to 10 GB of its own. Databricks says branching a 1 TB copy takes about as long as a 1 GB one: seconds. Every branch carries an expiry time, so a forgotten cleanup step can't leave a pile of stale databases behind, and the same trick gives AI agents a disposable copy of production to break.

Google's Elephant-Goldfish Model puts an agent between you and the code that never writes any code itself. Prasenjit Sarkar says [the open-sourced tool runs one long-lived Elephant agent that argues about the plan](https://x.com/stretchcloud/status/2116625003277881615), then hands a design doc to fresh Goldfish agents with zero memory of how it was written. One must explain the plan back before critiquing it, and a last one makes the go or no-go call. He says thousands of Google engineers run it daily; the bet is that an agent which remembers its own bad decisions will defend them, and a stateless one can't.

Apek open-sourced [AnyScene, which builds a whole Blender scene from one reference image](https://x.com/apekshik/status/2116638903923073290), plus optional text. He says the agent places, lights and color-grades the set and breaks every asset out as its own file. That last part is the useful one: a scene you can take apart is a scene an artist can actually keep editing.

An ICML 2026 paper on Self-Distillation Policy Optimization has the model reread its own failed attempt with the environment's feedback, then [train on what it would have said next, with no outside teacher](https://x.com/Pyuyi2333/status/2116622177805980065). On chemistry reasoning with Olmo3-7B it reached the accuracy of GRPO, a standard reinforcement learning method, about 6 times faster in wall-clock time. The catch, stated by the summary itself: it needs reliable feedback and a model strong enough to teach itself.

Quinten Farmer pushes back on the idea that Chinese labs are deliberately starving US inference margins. From running open models on Tolan's own infrastructure, he estimates [US providers can serve open-source models at roughly 45 to 60% gross margins](https://x.com/quintendf/status/2116626710007566673), against a reported 24.6% for Zhipu's API business in the first half of 2026. His read is that cheap Chinese inference reflects weaker hardware and a smaller buildout, not a price war. His math is back-of-the-envelope spot pricing, which he says doesn't prove equal realized margins.

That's the cycle. Go split your CI time into three buckets, branch a database instead of restoring one, and let a goldfish read your plan.
